## 本轮修复

同步清理原来会枚举并删除所有非活动分块，包含其他设备刚送达、尚未发布活动指针的分块。现在只清理本次提交明确替换的旧代，每批删除前确认活动指针没有被切换；未确认归属的分块予以保留。配额预检使用相同清理范围，不再假定这些分块可以被删除。

另一处问题是链接列表、活动指针和内容块独立送达时，旧代码可能把暂时找不到内容的链接或文件夹子项过滤掉。现在读取快照时先检查引用完整性；不完整则保留上次完整视图，禁止基于这份快照写入，待后续数据到达再恢复。

新增 5 个回归用例在修复前全部失败，修复后全部通过，覆盖远端暂存、活动指针切换、列表先到、内容先到和缺少文件夹子项。真实 Firefox 中也验证了远端暂存和列表先到两类场景。

这不是跨设备冲突合并。Firefox Sync 按键处理冲突，本机 Web Locks 无法锁住另一设备或同步服务；完整但相互竞争的修改、同 ID 不同内容、删除与编辑冲突以及清理读取与删除之间的跨设备竞态仍需解决。引用检查无法识别所有混合代数据，未知残留分块可能占用 Sync 配额，不能盲目清空它们。按用户最新决定，双设备冲突合并移至后续版本，首版不承诺该能力。同步语义依据 [MDN storage.sync](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync)。

## 大备份、压力与中断边界

128 MiB 样本是 16 个各 8 MiB 的二进制 Blob，OPFS 导出后恢复并逐个核对 SHA-256；不是 128 MiB 的真实照片渲染性能测试。

| 指标 | 稳定版 | ESR 140 |
| --- | --- | --- |
| ZIP 字节数 | 134,242,014 | 134,254,361 |
| 导出耗时 | 7.09 秒 | 12.22 秒 |
| 导出＋恢复＋校验 | 9.05 秒 | 16.99 秒 |
| 采样到的 Firefox 进程树工作集峰值 | 1,337,446,400 字节 | 1,162,002,432 字节 |
| 采样次数 | 12 | 20 |

工作集覆盖该测试浏览器进程树，包含浏览器基础开销；约 500ms 间隔加上采样开销，并非精确峰值或扩展独占内存。不同测试运行负载不同，不用于比较两版本性能，也不推出 500 MiB／2 GiB 阈值已经实测。

快速关闭 20 个标签页期间，每页启动 8 组后台消息和存储读取；原页面随后 20 个消息全部得到回复，本地标记保留。稳定版仍记录关页时 `JSWindowActorChild cannot send at the moment`，栈指向图库监听注册；ESR 记录关闭期间脚本加载取消。未见遗留页面或后台失效，但不声称控制台零错误或所有销毁竞态已消除。M3 的本机 HTTP 图片 CSP 拦截、M5 的 HTTP 拒绝属于已知测试诊断。

恢复中断测试在资产库导入完成、下一数据库导入前注入异常。结果正确返回失败，但图片库已恢复为备份内容，设置仍保留恢复前状态；随后用同一备份重新恢复成功。**目前没有跨数据库和 storage 的全局回滚。** 本用例证明错误可检测、受控中断后可重试，不证明断电／强杀后原状保留。发布前仍要确定失败恢复策略。
