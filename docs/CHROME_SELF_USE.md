固定扩展 ID：`ikjonccnpooflmknleniaiicpogiaieb`。构建声明最低 Chrome 116；本次实际验证 Chrome **154.0.8037.93**，最低版本未逐一实测。验证范围见同目录的 [验证记录](CHROME_SELF_USE_VALIDATION.md)。

## 首次安装

推荐使用 `ember-tab-0.1.3-chrome-self-use.zip`：

1. 把整个交付包解压到一个长期保留的目录。例如解压到 `D:\workspace\EmberTabChrome`，实际扩展目录就是 `D:\workspace\EmberTabChrome\chrome`。确认该目录直接包含 `manifest.json`、`newtab.html` 和 `scripts` 等文件；不要选择 ZIP 文件或外层交付目录。
2. 在 Chrome 地址栏输入 `chrome://extensions/`，开启右上角“开发者模式”，点击“加载已解压的扩展程序”，选择上述 **chrome 目录**。
3. 核对扩展名称 Ember Tab、版本 0.1.2，以及上述固定 ID。打开新标签页；如果 Chrome 询问是否保留新的新标签页，选择保留。
4. 从新标签页左下角设置按钮调整外观和数据。安装后关闭并重新打开 Chrome，确认新标签页和设置仍正常。

**保持开发者模式开启，并持续保留加载目录。** 当前测试 Chrome 关闭开发者模式会停用未打包扩展。扩展数据属于当前 Chrome 用户配置；相同 ID 并不意味着不同浏览器配置会自动共享本地数据。

也可使用普通运行包 `ember-tab-0.1.3-chrome.zip`：解压后直接选择包含 `manifest.json` 的根目录。普通包和自用交付包的 `chrome/` 运行文件逐字节一致。开发时可以直接加载本仓库的 `D:\workspace\aura-tab-firefox-assessment\dist\chrome`；该目录每次构建会重新生成，若想在写代码时继续使用稳定版本，采用上面的专用安装目录。

本地安装和重新加载操作参照 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。

## 从 Firefox 或旧 Chrome 包迁移

1. 在原扩展“设置 → 数据”中导出 ZIP 备份，确认文件已完整下载；保留原扩展和原始备份。
2. 如果目的端 Chrome 已有数据，先从 Chrome 导出另一份 ZIP，并用不同文件名保存。
3. 在固定 ID 的 Chrome 扩展“设置 → 数据”中选择导入原 ZIP，阅读并确认恢复提示。导入会替换可迁移的数据，不是追加合并。
4. 恢复后核对链接、文件夹、Dock 顺序、设置、本地壁纸和图片；再重启 Chrome 检查。确认成功后再自行处理旧安装。

第一至三步生成的早期 Chrome 包没有固定 `key`，因此 ID 会改变；仅覆盖旧目录不能自动转移旧身份的数据。先完成旧包导出，再加载固定 ID 包并导入。若两个版本同时启用，可在导出完成后停用旧版本，打开 `chrome-extension://ikjonccnpooflmknleniaiicpogiaieb/newtab.html` 确认目的端。

| 内容 | ZIP 迁移行为 |
| --- | --- |
| 快捷链接、文件夹、Dock、普通设置、本地图片和图标 | 恢复备份内的内容 |
| 搜索历史及新增搜索功能开关／来源 | 不进入备份；保留目的端本机内容，在 Chrome 单独设置 |
| WebDAV 登录配置和凭据 | 不进入备份；保留目的端已有配置，首次使用需重新填写 |
| 壁纸服务 API 密钥 | 普通备份包含这些配置；备份请自行妥善保管 |

Firefox 和 Chrome 的账号同步互不相通，本地图片通过 ZIP 迁移。本轮未验证未上架扩展的 Chrome 跨设备账号同步。普通包的图床、在线服务和 WebDAV 需使用 HTTPS。

## 自己修改代码后打包

在本仓库根目录，使用 Node.js 24 和 npm：

```powershell
npm ci
npm run package:chrome:self-use
```

输出：

- `dist/chrome/`：普通扩展目录，可直接加载。
- `dist/ember-tab-<版本>-chrome.zip` 和 `.sha256`：普通运行包与校验值。
- `dist/chrome-self-use/`：自用交付目录，含 `chrome/`、本说明、验证记录、`RELEASE.json` 和 `SHA256SUMS.txt`。
- `dist/ember-tab-<版本>-chrome-self-use.zip` 和 `.sha256`：上述目录的完整交付包。

只需要普通运行包时可执行 `npm run build:chrome`。版本由 `ember.project.json` 的 `currentVersion` 读取。保留该文件的 `chromePublicKey` 和 `chromeId`；构建会拒绝缺失、格式错误或不匹配的身份配置。manifest 的 `key` 用于维持开发安装 ID，参见 [官方 key 说明](https://developer.chrome.com/docs/extensions/reference/manifest/key)。

验证记录明确记录本次接受检查的包哈希；新改动生成的包不会自动继承旧验收结论。`RELEASE.json` 的 `matchesValidatedRuntime` 会表明当前运行包是否与本次已验证包一致。根据实际改动运行功能或生命周期检查后，再更新验证记录。

## 手动更新

1. 从当前 Chrome 扩展导出 ZIP，另存好旧版本的扩展文件。关闭现有 Ember Tab 页面，避免更新期间编辑数据。
2. 构建新包并解压到临时目录，先核对新目录的 manifest 版本和固定身份。不要把整个交付包外层覆盖到扩展根目录。
3. 将新包内 **chrome 目录的全部运行文件**替换到原来加载的目录，清除旧版本多出的运行文件。浏览器中的扩展保持安装状态；更新文件目录不等于删除浏览器用户配置。
4. 在 `chrome://extensions/` 的 Ember Tab 卡片上点击“重新加载”，打开一个新的新标签页，核对版本、ID、设置、链接和本地图片；再重启一次 Chrome。

**更新时不要先卸载扩展，也不要更换公钥或删除浏览器配置。** 如果直接加载的是 `dist/chrome/`，重新构建后执行第 4 步即可。若使用专用安装目录，构建不会自动更新它，仍需执行第 3 步。

文件路径变更虽然通过了同 ID 保留数据测试，日常更新仍建议沿用同一目录。新增权限、数据结构变更或新 Chrome 行为需另行验证。

## 图标候选选择

在新增／编辑链接窗口，选择“自动”样式，再点击“选择图标”。列表展示当前缓存和网站、浏览器、Google、Vemetric 返回的可用图片及尺寸；打开列表会请求备用服务，但不会自动替换当前图标。点击候选后立即应用，无需保存按钮；修改链接字段仍需保存。关闭窗口不会撤销已经点击应用的图标。

选择存在本机图标缓存中，普通链接编辑和页面重载会保留它，不随快捷链接账号同步。再次点击“刷新图标缓存”会恢复自动选择；清空缓存后也需要重新选。更大的画布不一定更清晰，建议直接比较候选外观。

公共 HTTP 链接取图时会先尝试对应 HTTPS 页面，不改变保存的导航地址；内网 IP、本机地址和显式非默认端口保持原取图地址。没有可用原站图时仍使用既有回退来源。Chrome 普通包的 HTTPS 权限和固定 ID 不变。

## 回退和恢复

若仅新代码不能正常工作，先保留当前数据，恢复此前保存的整套运行文件到同一目录并重新加载。涉及数据结构变更时，应使用明确兼容该备份的版本；本次只验证了 0.1.2 同结构更新测试。

若需恢复迁移前内容，在“设置 → 数据”中导入迁移前另存的 Chrome ZIP；取消导入不会改动数据。本次已验证正常导入、取消以及迁移后手动恢复。恢复不具备跨 storage 与多个数据库的全局自动回滚；重要资料应始终保留独立备份。

## 文件校验与常见问题

交付包旁的 `.sha256` 校验整个 ZIP；解压后的 `SHA256SUMS.txt` 校验运行文件和说明文件。Windows 可对下载的 ZIP 执行：

```powershell
Get-FileHash -Algorithm SHA256 .\ember-tab-0.1.3-chrome-self-use.zip
```

将结果与同名 `.sha256` 的第一段进行比较。`RELEASE.json` 还记录普通运行 ZIP 的字节数、哈希、版本、固定 ID 和测试哈希匹配情况。校验值用于核对文件一致性；这不是商店签名。

| 现象 | 处理 |
| --- | --- |
| 无法加载、提示缺少 manifest | 选择解压后直接含 `manifest.json` 的 chrome 目录 |
| 重启后扩展被停用 | 检查开发者模式、扩展开关和加载目录是否仍存在 |
| 新标签页仍被其他扩展占用 | 在扩展页检查其他新标签页扩展，并按自己的选择调整启用状态 |
| 更新后还是旧页面 | 重新加载扩展，再关闭旧页面并打开新标签页；核对实际加载路径 |
| YouTube 自动图标模糊 | 本包已修复大页面图标发现及低分辨率选择；更新后编辑 YouTube 链接并点击“刷新图标缓存”。永久缓存不会因更新被批量清空 |
| 千问、谷歌翻译刷新后图标模糊 | 本包优先可靠原站图，匹配当前主题并过滤已确认的备用占位 SVG；更新后重新加载，再逐项刷新。更大的图片画布不代表更多细节 |
| Mini4K、Lunaris 刷新后图标模糊 | 本包保留至少 32 像素的原站图；需要备用服务时优先 Google 返回的可用图，再回退 Vemetric。更新后分别刷新图标。原图像素有限，放大显示仍可能不够清晰 |
| 腾讯新闻、B站的 HTTP 链接图标模糊 | 本包先尝试 HTTPS 原站取图；重新加载后刷新缓存。仍不满意时，点“选择图标”自行比较候选，导航地址无需修改 |
| 导入后没有搜索历史或 WebDAV 登录信息 | 这些数据不随 ZIP 迁移，按上表在目的端设置 |
| ZIP 导入或下载失败 | 保留原安装和备份，检查文件是否完整、扩展错误及下载工具接管情况，成功前不要删除原数据 |

交付运行目录保留 `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`、`licenses/` 和 `privacy.html`。测试 HTTP 包、测试版本 0.1.3、浏览器配置和迁移备份均不属于本交付包。
