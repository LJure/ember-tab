## 0. 准备测试环境

1. Firefox 地址栏输入 `about:profiles`，创建 `Ember-M4-Backup`，在新浏览器窗口启动。确认日常配置仍是默认配置；创建配置可能改变默认项，可在该页面设回原配置。A、B 测试不登录 Firefox 同步账号。
2. 在新配置打开 `about:debugging#/runtime/this-firefox`，点“临时载入附加组件”，选择：

   `D:\workspace\aura-tab-firefox-assessment\dist\firefox\manifest.json`

   不要选仓库根目录的 Chrome manifest。新建标签页应出现 Ember 页面。当前界面仍可能有 Aura 字样，品牌替换在 M5。
3. 另一台电脑可复制 `dist/ember-tab-0.1.0-firefox.zip`，解压到固定文件夹，再临时加载其中的 manifest。两端使用同一包，ID 为 `ember-tab@ljure.github.io`。
4. 当前 ZIP SHA-256：`78938eb4f6f30add42fa5a8dd85b003aef28f3a6b620ffafa5d8245f7a3d2475`。记录 Firefox／Chrome 和 Aura 版本；Firefox 低于 140 不在当前目标范围。
5. 使用可丢弃的测试链接、图片和云端目录。导入会覆盖测试配置里的扩展数据；不要用唯一一份日常数据做恢复实验。备份可能包含链接和已保存的图片 API 设置，不必上传完整 ZIP，也不要回传密码／令牌。

临时扩展在 Firefox 完全退出后移除；重新进入同一测试配置时按第 2 步加载，数据保留另行核对。这不是正式签名安装。参考：[Mozilla 临时安装](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)、[配置管理](https://support.mozilla.org/en-US/kb/profile-manager-create-remove-switch-firefox-profiles)。

## A. Chrome 实际 Aura 备份迁移

建议使用 Chrome 单独测试配置中的 Aura Tab。已验证的上游格式基线是 3.5.3；如果商店版更新了，记录实际版本，不必降级日常安装。

1. 在 Aura 中准备 5 个链接（包括中文标题），1 个装有 2 个链接的文件夹，调整顺序并固定 2 个链接到 Dock；上传 3 张能区分的本地图片，选择其中一张作壁纸，改变裁剪位置。设置主题、语言、搜索引擎并记下值。
2. 截图或写下上述状态。使用设置中**完整本地备份的“导出”**生成 ZIP，不是快捷链接专用的 JSON／HTML／CSV 导出，也不是 Chrome 书签导出。
3. 在 Firefox 的 Ember 设置中进入数据相关页面，在“本地备份”的“导入 / 导出”区域点“导入”，选择该 ZIP，确认覆盖测试数据，等待提示和页面重载。
4. 逐项核对链接总数、名称、网址、文件夹子项、顺序、Dock；点击链接确认目标正确。核对 3 张本地图片、缩略图、当前壁纸和裁剪、主题、语言、搜索设置。网站图标可能重新下载，记录缺失／回退情况；不要只凭页面打开就判通过。
5. 刷新，再开一个新标签页，再核对一次。导出 Ember 完整 ZIP；把一个链接改名为 `临时修改`、切换壁纸，再导入刚导出的 Ember ZIP，确认原状态恢复。

预期：两次恢复都成功，以上数据可核对。出现“部分旧缓存未导入”时，记录提示及受影响的图标；这属于带限制的恢复，不按完全一致勾选。失败时保留原 ZIP，不要反复覆盖日常配置。

回传：Chrome／Aura／Firefox 版本、ZIP 大小、各项一致或差异、错误原文。不需要发送整个备份。

## B. 真实 WebDAV

准备一个已有 WebDAV 服务，使用服务商提供的 HTTPS WebDAV 地址及应用密码（若该服务要求），凭据只填在浏览器界面。建议有写入和删除测试目录的权限。

1. 在 Ember 设置 →“云端备份（WebDAV）”填写服务器地址、用户名、密码；远端目录用独立的 `EmberTab-M4-Test`。点击“测试连接”。
2. 确认本地有测试链接和图片；点“立即备份”，等待完成，再点“刷新列表”。应出现新备份，文件大小大于零。用服务商网页／客户端确认对应目录里确有 ZIP。
3. 修改一个测试链接名称及壁纸；在备份列表中恢复刚上传的版本。应恢复原名称、图片和设置；WebDAV 配置应仍可用。重载后再次刷新列表确认连接没有丢失。
4. 将远端目录改为 `EmberTab-M4-Test/中文 空格#100%`，再备份、刷新、恢复一次。若基础目录通过而特殊目录失败，分别记录；服务商拒绝某些字符时记录实际限制。
5. 在该专用目录内删除本轮生成的一个备份。扩展列表和服务商端都应不再显示该文件，其他版本仍在。不要删除已有个人备份。
6. 错误路径：临时把应用密码改错，点“测试连接”和“刷新列表”。应明确报错，不能报告连接成功或把拒绝访问当成正常空列表。然后恢复正确密码。
7. 可选权限路径：若服务支持只读账号／目录，用它尝试备份。应失败且不显示“备份成功”；没有只读条件则记未测，不必修改正式目录权限。
8. 可选断网路径：用较大的测试包，在上传或下载进行中断网，再恢复网络后重试。记录是否报错、等待时长、远端是否残留不完整文件、重试是否成功。断网须发生在传输中，不在“恢复图片／写入数据”阶段强制结束进程。若生成残留 ZIP，记录其恢复是否被拒绝，不要在正式数据上试。

传输默认超时最长 30 分钟。60 秒仍等待只能记为“尚未结束”，不能提前记通过或失败；无需为了本轮协助一直等满 30 分钟，可回报现象让我继续诊断。

回传：服务名称／部署类型、HTTPS 与否、普通和特殊目录是否通过、ZIP 大小、上述步骤结果和错误原文。地址可隐去域名或账号目录；不要发送密码、Authorization 请求头或整份网络日志。

## C. Firefox 账号 Sync

最好用两台桌面电脑；一台电脑的两个独立配置也能验证经账号服务同步，但不计为两台设备通过。不能用同一配置开的两个窗口替代。A、B 各自临时安装同一个包，登录同一 Mozilla 账号，在 Firefox 同步设置勾选“附加组件”。优先使用专门测试账号，避免测试影响同账号日常配置的扩展状态。

此项仅验证本项目写入 `storage.sync` 的设置／快捷链接。IndexedDB 本地图片、图标缓存和 WebDAV 本地配置不通过 Firefox Sync 复制；跨浏览器迁移图片请用 ZIP。Firefox 按键同步，服务端变更可能覆盖本地，不提供本项目数据的跨设备原子合并。[Mozilla Sync 说明](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync)

1. 两端先各“立即同步”一次，等待浏览器同步结束。在 A 设纯色背景以避免图片依赖，新增 `SYNC-A-1` 链接，改变主题；A 点“立即同步”，完成后 B 点“立即同步”。观察 B 正在打开的 Ember 页，再刷新核对。未出现时等约 10 分钟再执行一次 A → B，同步仍无变化则记录，不反复重装。
2. B 修改该链接标题为 `SYNC-B-EDIT`，新增 `SYNC-B-2`；按 B → A 顺序同步。A 应收到修改和新链接。再从 A 删除 `SYNC-B-2`、调序，按 A → B 同步，确认删除和顺序到达。分别记录无需刷新与刷新后的结果。
3. 进入分块样本：使用测试书签文件夹导入约 80 个标题短、网址普通的测试链接，或手动准备等量样本。先核对 A 数量，再 A → B 同步，比较总数、文件夹、顺序、Dock，抽查开头／中间／末尾链接。若不便准备，先做步骤 1–2，标记分块样本未测；80 条样本不保证一定跨块，由后续诊断确认。
4. 基础同步通过后，再做冲突测试。两端先完全同步到相同状态，各导出一份完整测试备份。让两端断网或各自进入 Firefox“脱机工作”，A 新增 `OFFLINE-A`，B 新增 `OFFLINE-B`。先恢复 A 并立即同步，再恢复 B 并立即同步，最后 A 再同步一次。记录两条新增项各自是否存在、既有链接总数、是否有整页消失／重复／无法编辑。
5. 再测同一链接冲突：两端先同步一致；离线时 A 把同一链接改名为 `CONFLICT-A`，B 改为 `CONFLICT-B`。按 A → B → A 同步，记录最终标题及两端是否收敛。同一字段可能被覆盖，不要求同时保留两个标题；不同新增链接的丢失、整批消失或不能继续编辑需要修复，不能因为符合底层按键覆盖就算项目通过。

Mozilla 说明扩展数据约每 10 分钟同步，或由“立即同步”触发。两端都要执行同步，并记录顺序；仅登录账号不能证明完成了同步。若基础用例无变化，提供两端版本、是否勾选附加组件、最后同步时间和现象，我再判断服务条件与扩展行为，不要求你修改高级参数。[同步频率与冲突规则](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync)

| 真实图片较大样本 | 先 20 张，再约 100 张测试图片，逐档完整导出、导入，核对数量和抽查显示；普通本地与 WebDAV 可分别做 | 记录原文件总量、实际 ZIP 大小、耗时、任务管理器 Firefox 基线／最高内存；缩图后实际数据可能远小于源图片，未超过 32 MiB 就不计为更大容量验收 |

| ESR | 如已有 ESR，用其独立配置重复加载、链接操作、图片和备份往返 | 记录实际版本；不要让旧 ESR 打开日常新版 Firefox 的配置 |
| 正式安装／升级 | 等后续签名测试包及版本提供 | 当前标记未测，无需调整签名校验设置 |

以上发生失败后，先保留现象，不用重复清空数据。错误详情可从 `about:debugging` → Ember Tab →“检查”→“控制台”取得；打开检查器会影响后台休眠，生命周期问题请先在不打开检查器时复现，再抓取错误。只提供相关错误行及脱敏截图。
