# Chrome YouTube 自动图标清晰度修复

> 后续：首次修复的尺寸优先级导致千问／谷歌翻译回归，已进一步修正原站优先、主题匹配与占位图过滤。见 [后续图标来源修复](CHROME_ICON_SOURCE_FIX.md)；本页包哈希和检查数量保留为首次修复时的历史记录，当前交付以 [验证记录](CHROME_SELF_USE_VALIDATION.md) 为准。

2026-10-03，仍为本地自用版本 0.1.2，固定 Chrome ID 保持不变。未操作用户日常浏览器配置或当前缓存。

## 复现和原因

在独立 Chrome 154.0.8037.93 配置中，对 `https://www.youtube.com/` 和 `https://youtube.com/` 使用普通扩展的现有取图逻辑，均复现：

1. YouTube 首页 HTML 超过 512 KiB，原 `fetchLimited` 报 `Response too large`，因此没有解析首页实际声明的 32／48／96／144 像素图标。
2. Chrome `/_favicon/` 的请求参数虽为 `size=128`，实际解码结果是 **64×64**。本次干净配置中，该图像是默认地球占位图；用户日常配置可能有另一个已缓存的站点图标，不代表已读取其当前缓存。
3. 旧逻辑将不小于 32 像素的原站／Chrome 图标视为可用，只在这些候选全部失败时访问 Vemetric／Google。两者在本次请求中均实际返回了 **128×128** 的 YouTube 图标，却没有进入原自动选择流程。
4. 手动刷新会重新执行同一发现逻辑，所以清除或刷新缓存后仍会选到低分辨率结果；这能够解释报告的症状。未确认用户图标变化的具体时间或当时的 Chrome 缓存内容。

旧代码证据：`.local/youtube-icon/run-1791006888154/report.json`；旧普通运行包 SHA-256 为 `e36996d0f7114fbe207eb70e57ae9f3cb94e7043ccc016b10e632d7e7191f9f9`。

## 修复

- 网页元数据采用严格限制为 512 KiB 的 HTML 前段，即使完整页面更大，也保留已出现的 favicon 链接；达到边界立即取消流，不完整下载整页。3 秒超时仍有效，图片和 manifest 的完整性／字节限制保持原要求。
- 按实际解码尺寸判断清晰度，128×128 或 SVG 才视为足够。存在更清晰图片时，它不会被来源分数更高的低分辨率图片覆盖；清晰度足够的候选之间仍优先站点声明。
- 原站／Chrome 只有低分辨率结果时，继续尝试现有备用来源；备用失败仍保留原来可用的小图，不把链接变成空图标。
- 缓存保留原图字节，不用强行放大来制造清晰度。自定义图标的取图和显示路径不受本次选图规则影响。

没有硬编码 YouTube 的部署目录或某张图的地址。实际新选择为网页声明的 `favicon_144x144.png`，解码结果 **144×144**。本次原站结果足够清晰，因此无需备用服务参与自动选择。
