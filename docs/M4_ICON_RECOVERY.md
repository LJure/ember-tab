## 原因与修改

后台 `fetchIcon` 原来对所有图片使用 3 秒期限；页面候选图片回退也每 3 秒切换。用户指定图床图片与自动寻找网站 favicon 共用这组限制，慢图片即使有效也会被放弃。本次样本约 420 KiB，低于既有 512 KiB 限制，因此该样本不是容量拒绝。

- 显式指定的自定义图片使用 60 秒网络期限，覆盖响应体读取；自动网站图标发现继续保持原期限和尺寸限制。
- 后台最多同时进行 4 个自定义图片任务；同 URL 的并行请求合并。网络错误、超时、429 和 5xx 最多重试一次，间隔 1 秒；404、图片过大、无效图片不做该重试。
- Dock、启动台、链接管理和编辑预览等待时显示文字占位。成功后移除占位并显示图片；失败保留可读文字。只读编辑预览也使用慢图策略，但不写缓存。
- 图床下载成功后按原规则写 IndexedDB 图标缓存；已有缓存可复用。缓存写入失败时仍显示已下载的图片，不把“不能缓存”当作“图片无法显示”。
- 自定义图片的直接加载回退也使用 60 秒期限，并保留指定图片的选择，不擅自换成网站的其他 favicon。失败后不写自定义图片的长期失败缓存，重新开页或刷新可以再次尝试。

期限从实际开始请求计，不含排队时间。60 秒仍不是所有图床都能保证成功的承诺；两次后台尝试加直接图片回退可能继续等待较长时间，此时显示文字占位。缓存仍为单图 512 KiB、总量 20 MiB；超过缓存容量的图片可能走直接加载，不能承诺离线复用。图片内容仍只保存在本地，Firefox Sync 只带来链接及图片地址。

## 用户复验步骤（已收到通过反馈，保留供回归使用）

1. 本机临时安装若指向 `dist/firefox/manifest.json`，在 `about:debugging#/runtime/this-firefox` 点击 Ember 的“重新载入”，再新开标签页。其他电脑复制最新 `dist/ember-tab-0.1.0-firefox.zip`，解压后重新加载其中的 manifest；ID 和版本仍为原值。
2. 不必重新导入备份或清空数据。打开启动台，观察斗鱼及原来缺失的图标；慢图片等待时应显示文字，加载完成后替换为图片。图标多时任务会排队。
3. 成功后再开一个新标签页，检查同样图片是否从缓存较快显示；如仍缺失，记录图标名称、等待时间、是否始终为文字，以及单独打开图片是否成功。
4. 用户已确认复验通过，图标待办关闭；真实 Sync 的并发冲突场景仍需独立验收。
